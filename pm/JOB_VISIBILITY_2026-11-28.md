# Student vs HR Job Visibility and Cache Isolation (2026-11-28)

## Root Causes
Live API checks on `studentjob-demo-vps` confirmed the backend already served 150 `OPEN` + `APPROVED` jobs on `GET /api/jobs` (96 `PART_TIME`, 40 `FULL_TIME`, 14 `INTERNSHIP`, all owned by `employer_profile` 1 / user 3) and 150 own jobs on `GET /api/jobs/mine` for `employer@studentjob.example.test`. Four active accounts exist in the demo database (no second employer account). Three frontend state/cache defects caused job visibility failures across HR, Guest, and Student flows:

1. **Role-conflated job cache (`frontend/src/services/store.ts`)**: `jobService.load()` wrote `GET /api/jobs/mine` into the single shared `jobCache` when `session?.role === 'EMPLOYER'` instead of keeping public marketplace jobs (`GET /api/jobs`) separate from employer-owned jobs (`GET /api/jobs/mine`) and admin pending jobs (`GET /api/admin/jobs/pending`). Any HR user without the 150 seeded jobs saw 0 jobs on public `/jobs`, `/`, `/companies`, and `/jobs/:id`.
2. **SPA logout and role-switch cache starvation (`frontend/src/App.tsx`, `store.ts`)**: Workspace `Đăng xuất` cleared `jobCache = []` and navigated via SPA `navigate("/")` without reloading public jobs, and `Login` skipped `jobService.load()` for `STUDENT`. In headless Chrome on the live demo, Employer -> Logout -> Student -> `/jobs` reproduced `Vị trí đang mở tuyển 0`.
3. **Session sync and expired-auth notification gap (`App.tsx`, `store.ts`)**: `api.auth.me()` set React `user` state without syncing `store.setSession(restored)` before calling `jobService.load()`, and when stale `EMPLOYER` credentials hit 401 on `/api/jobs/mine`, the `sessionEpoch` bump caused `publicJobCache` updates to be discarded or skip `notifyData()`.

## Fix Summary
- Split `store.ts` caches into `publicJobCache` (`jobService.all()`), `employerJobCache` (`jobService.mine()` / `jobService.mineById()`), and `adminPendingJobCache` (`jobService.adminAll()`), each with its own load-version guard (`publicJobLoadVersion`, `employerJobLoadVersion`, `adminJobLoadVersion`) and `sessionEpoch` isolation for private caches.
- Preserved `publicJobCache` across logout, role switches, and `/api/jobs/mine` failures, and triggered `notifyData()` immediately upon updating `publicJobCache`.
- Updated `App.tsx` so `EmployerDashboard`, `EmployerJobs`, `JobEditor`, `EmployerApplications`, and `ApplicationDetails` (for `EMPLOYER`) read `jobService.mine()` / `jobService.mineById()`; `AdminDashboard` and `AdminJobs` read `jobService.adminAll()`; `api.auth.me()` syncs `store.setSession(restored)` first; `Login` reloads `jobService.load()` for all roles; and Workspace logout / `/jobs` / auth-expiration paths recover cleanly if `publicJobCache` is empty.
- Added regression tests in `frontend/scripts/job-mapping.test.cjs` covering zero-own-job employers, `/jobs/mine` failure isolation, logout cache isolation, mid-flight generation/epoch guards, and stale-401 public job preservation.
